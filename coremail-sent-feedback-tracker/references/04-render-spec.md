## 1. 固定三件套

| 文件 | 语言 | 内容规则 |
|------|------|----------|
| `<项目>_CN.html` | 中文 | 问题、总结为中文；**回复内容保留原文** |
| `<项目>_EN.html` | 英文 | 问题、总结为英文；回复内容为原文。**零中文残留**（硬规则） |
| `<项目>.md` | 中文 | Markdown 总结，含手工待办 + 未解决事项清单 |

**默认文件名**（换项目时在 `main()` 里改）：

```

HP客户问题回复汇总_EN.html
HP客户问题回复汇总.md
```

### 2.2 邮件切换器（下拉）

> **用户原话**：「上方的切换邮件标题的 tab 栏占用的面积太大了，有可能变成下拉列表吗？」

- 单行结构，`position:sticky; top:0`，高度约 **48px**（原多行页签最多占 3 行 ≈ 120px+）
- 结构：`[‹] [ M1 · 标题(截断) · 21 条目 · 1/16 · ▼ ] [›]`
- **`‹` / `›`**：上一封 / 下一封（首末封自动 `disabled`），键盘党不用展开下拉
- **下拉项**（两行网格 `grid-template-columns:38px 1fr`）：
  - 左列：编号
  - 右列第一行：**完整邮件标题**（`m.subj`，允许换行、**不截断**）
  - 右列第二行 `.ddo2`：`发件人 <邮箱>` / `发送时间` / `条目数` / `状态四色小计数`
  - ⚠️ **列表项用 `m.subj`（全文），折叠态按钮仍用 `m.chip`（截断）**
- **下拉内筛选框**：按 `编号 + 标题 + 发件人 + 发送时间` 过滤
- **hover 提示**（用户明确要求，保留）：`title` 属性三段，用 `&#10;` 连接换行 ——
  ① 完整邮件标题 ② `发件人：<名> <账号>` ③ `发送时间：…`；英文页对应 `From:` / `Sent:`
  **下拉按钮和每个选项都带这个 title**
- **交互约定**：`Esc` / 点外部 / 选中某封 / 点状态 chip / 在正文搜索框输入 → 自动收起下拉
- 下拉面板 `max-height:min(62vh,560px)`（下拉面板滚动是弹层行为，与「回复内容不要内滚动」不冲突）
- 关键变量：`ddOn`（展开态）、`ddQ`（筛选词）；`tabs()` 在每次 `render()` 里重建，靠这两个全局量保状态
- 函数：`tabs()` 出工具栏 / `ddList(q)` 出列表 / `ddToggle()` / `ddFilter()` / `pick(i)` / `step(±1)` / `ea()` 属性转义

### 2.4 明细表

**固定列（顺序不可变更）**：

```
问题 | 负责人(Owner) | 问题回复内容 | 问题回复总结
```

**列宽**（`table-layout:fixed`）：

| 列 | 宽度 |
|----|------|
| 问题 | 20% |
| 负责人(Owner) | 200px |
| 问题回复内容 | 26% |
| 问题回复总结 | 自适应（**最宽列**） |

**回复内容列不做内滚动**（用户明确要求「不要内滚动」）：

```css
.raw { /* 不得设 max-height / overflow-y */ }
```

长英文原文必须全文展开。

**校验方式**：生成的 HTML 里 `max-height` **恰好 2 处** —— 只允许这两个：

| 位置 | 值 | 为什么允许 |
|------|-----|-----------|
| `.ddlist`（下拉面板） | `max-height:min(62vh,560px)` | 下拉面板滚动是**弹层行为**，与「回复内容不要内滚动」不冲突 |
| `.todo ol`（Open items 清单） | `max-height:240px` | 同上，避免清单把表格挤下去 |

**多于 2 处 = 有人在回复内容里加了内滚动**，必须改掉。
（2026-10-04 实测基线：CN 与 EN 页均为 2。）

## 4. 手工备注区

### 4.1 位置与形态

**位置**：每行 `问题回复总结` 单元格内容**下方**（`td.sum` 里的 `.memo` 块），**不新增表格列**。

```
折叠态（唯一默认态）☐ 标记为已解决   [已解决]   备忘预览（灰字一行）   [＋ 备忘 / 结论]
                  ↓ 只有点按钮才展开（有内容也不再自动展开）
展开态          ☐ 标记为已解决
                备忘 / 最终结论   [textarea 3 行]
```

- 按钮文案：无内容 `＋ 备忘 / 结论`，有内容 `编辑备注`
- **默认收起**：`memoHTML()` 恒输出 `class="memo"`，
  `flush()` **不再**因「已解决 / 有备注」加 `open`。
  收官态与每次 `render()`（切邮件 / 搜索 / 筛状态）都回到收起 ——
  收起时靠「已解决徽标 + 备忘预览灰字 + `tr.solved` 淡绿底」表达状态，不靠展开
- **输入即存**：`input` 事件 → 写 localStorage，**不重新 render**，不打断输入焦点
- **已解决**：`change` 事件写 `s:1`；该行加 `tr.solved` → 淡绿底 + 总结列左侧 3px 绿条

### 4.2 存储

- localStorage key = `<前缀>_memo_v2`（换项目时**必须换前缀**，否则不同项目标记串）
- 结构：`{v: 版本号, d: {条目键: {s, n}}}`
  - `s` = 已解决，`n` = 备忘/结论**单字段**
  - 早期版本是 `{s, n, f}` 两框（`n`=备忘、`f`=最终结论）；
    加载时自动把 `f` 合并进 `n` 并删除 `f`（见 JS 里的 legacy 迁移段）
- **条目键 = `邮件号 + '-' + md5(问题纯文本)[:10]`**（`item_key()`）
  - 用**问题文本哈希**而不是行号 → 重跑后增删条目、顺序变化，备注仍能对上
  - **中英文两页共用同一个键**（两边都拿 `it["q"]` 中文原文算哈希）→ 备注在两页互通

### 4.3 工具条

搜索栏下方：`[导出 / 导入备注]` + `[保存到本页文件]` + 状态文字 `.fst` + 说明文字。

弹层内有 `复制` / `下载文件` / `导入这段 JSON` / `清空全部备注` / `关闭`，`Esc` 或点遮罩关闭。

### 4.4 写回本页文件

**实现**：File System Access API。

```
点 [保存到本页文件]
  → showSaveFilePicker({suggestedName: 当前文件名})
  → 用户确认覆盖原文件
  → 句柄存进 FSA
  → 首次之后每次改动自动写回（mset() → autoWrite()，防抖 2s）
  → 状态文字变绿「已连接本页文件 · 改动自动写回」
```

- **刷新页面后句柄丢失**（浏览器不允许跨会话持权），需再点一次按钮重连；之后又自动
- 未连接时状态显示「未连接文件（仅存本机浏览器）」，标记仍照常存 localStorage

**写回原理**：`document.documentElement.outerHTML` 整页序列化 → 定位并替换烘焙位

```js
// 渲染时输出：var BAKED = /*MEMO-S*/{...}/*MEMO-E*/;
// JS 里用拼接后再 indexOf —— 直接写完整字面量会先命中源码里自己的那串文本
var S = '/*M' + 'EMO-S*/', E = '/*M' + 'EMO-E*/';
```

替换前做转义，避免备忘里写了 `</script>` 破页：

```js
var U003C = String.fromCharCode(92) + 'u003c';
html = JSON.stringify(LS).split('<').join(U003C);
```

> 这样写**完全避开 Python 三引号吃反斜杠的坑**。

⚠️ **写回时必须 `LS.v = (LS.v || 0) + 1` 再 `persist()`**（关键！）：
否则新浏览器打开时 `BAKED.v(0) > LS.v(0)` 不成立，烘焙好的标记会被空的 localStorage 盖掉，
**等于白存**。这条只有跑「写回 → 当新页面重新载入」的往返测试才会暴露。

**降级链**：`showSaveFilePicker` 不存在（Firefox / Safari）或被拒（`SecurityError` / `NotAllowedError`）
→ 自动改为**下载一份更新后的同名副本**并提示替换原文件。
`file://` 下 Chrome 一般可用，但不保证，所以**降级路径必须留着**。

### 4.5 与自动状态的关系

| | 来源 | 覆盖关系 |
|---|------|----------|
| `st`（已确认/部分/转交/未回复） | **从邮件分析出来的** | 互不覆盖 |
| 手工「已解决」 | **我方判断** | **并列显示** |

要的正是「系统状态还是 No reply，但我线下已经解决了」这种并行记录。

## 5. 统计与未解决清单

### 5.1 顶部三张卡片（**全局**）

| 卡片 | 值 |
|------|-----|
| 已解决 | `Σ s=1` |
| 未标记 / 未解决 | `Σ条目 − Σ已标记解决`（JS `openCount()`） |
| 已加备注 | `Σ n 非空` |

- **初始值由 Python 侧算好写死**（`_sol0` / `_open0` / `_memo0`，用 `item_key()` 只数当前清单命中的键）
  → 脚本未执行 / 首帧也能显示真实数字，**不会闪 0**
- 统计**只遍历当前清单里的邮件条目**（`MAILS[i].items[j].k`），
  **不要用 `STORE` 的键总数** —— 历史遗留键或非清单邮件的键会把「未解决」算成负数
  （已用 `Math.max(0, …)` 兜底）
- 每封邮件头卡片右侧多一行本封 `未解决 N`（`updStats()` 按当前邮件重算）
- MD 版同步多一行 `未标记 / 未解决：N 条（= 问题条目 X − 已标记解决 Y）`

### 5.2 Open items 动态清单

> **用户原话**：「Open items awaiting our response 改为 Open items，只展示那些未标记未resolved的问题」

- 标题：中文「未解决事项」/ 英文固定 `Open items`；`todoc` 显示条数
- 结构：
  ```html
  <div class="todo">
    <div class="th">未解决事项<span class="tc" id="todoc"> N</span></div>
    <ol id="todol">…</ol>
  </div>
  ```
- 每行形如 `M10 · 4.2 Automatic EDD Bypass Rules`，点击 `jump(i)` 切到该邮件并滚到表格
- 初值 Python 侧算好写死；JS `updTodo()` 挂在 `updStats()` 末尾重算 —— 与顶部卡片同一集合
- `ol` 限高 **240px** 滚动，避免把表格挤下去
- **数据不删**：`todos`（含 `held_todos`）仍留在数据文件，只是 HTML 不再渲染；
  MD 版保留原「当前待我方回应 / 跟进」小节，并**另加**「未解决事项（未标记为已解决）」清单

**行标题用 `short_q()`**：

```python
# 1) 先取 <br> 前的主句（中英都把正文放在 <br> 之后）
# 2) 再去标签
# 3) 超 88 字截断
```

⚠️ **不要按 em dash 二次切割** —— 英文标题里的 `— Puah's 09-10 reply` 正是区分两条未完项的标识，
切掉后列表里会出现两行一模一样的 `2.1 ETB Asset Values @Puah`。
**补充规则**：` — ` 之后若超过 44 字（说明是正文而非小标题）才整段丢弃。

### 5.3 筛选 chip

状态 chip 末尾多两个：

| chip | 内部值 | 数字口径 |
|------|--------|----------|
| 已解决/有备注 N | `fs==='MEMO'` | 全局 |
| 未解决 N | `fs==='OPEN'` | **当前邮件**（与其它状态 chip 同口径 —— 点开看到的行数和数字对得上） |

- 悬停有 `open_tip` 说明口径
- **备忘文本也进了搜索关键字**，可以搜备注里的内容

## 6. 英文版「零中文」硬规则

### 6.1 渲染器内置的 `en_clean()`

1. 删除问题里的**中文**附加子句 `<span class='sub'>…</span>`（中文版保留，英文版剔除）
2. 把 `<span class='warn'>⚠ 中文…</span>` 通过 `EN_WARN` 映射表换成英文等价表述
3. **数据层**仍需人工保证 `qe` / `se` / `raw` 里没有中文（无法靠正则兜住）

### 6.2 两条关键规则（踩过坑，别改回去）

**① 只剔除「含中文」的 sub 子句**

部分条目的 `qe` 里 sub 子句本身就是**英文**，那是有效信息，不能删。
实现：对 sub 内容做 `[\u4e00-\u9fff]` 判定，命中才删。

**② 中文版的 `q` 必须原样输出，只有英文版才过 `en_clean`**

> 曾经写成 `q = en_clean(it["q"]) if lang == "zh" else …`，导致**中文版的问题子句被静默剥掉**
> （CN 页面看不出来，但 `class='sub'` 计数从 156 掉到 2）。
> 改完务必核对：**CN 页 `sub` 计数应有上百个，EN 页 CJK 应为 0**。

### 6.3 扫描必须覆盖整个文件

**中文写在 CSS 注释 / JS 注释里也会被命中。**
（实测：`/* ---------- 页签 ---------- */` 这类注释让 EN 页残留 3 处 CJK；
内嵌 JS 里的中文注释同样算，加「旧数据兼容」注释时又踩了一次 31 处。）

> **结论：`JS` / `CSS` 字符串里的所有注释一律写英文。**

```bash
python -c "
import io, re
s = io.open('xxx_EN.html', encoding='utf-8').read()
# 广义 CJK：汉字 + 中文标点(\u3000-\u303f) + 全角符号(\uff00-\uffef)
print('CJK:', len(re.findall(r'[\u3000-\u303f\u4e00-\u9fff\uff00-\uffef]', s)),
      '| max-height:', s.count('max-height'))"
```

**期望输出**：`CJK: 0 | max-height: 2`

> ⚠️ **只扫 `[\u4e00-\u9fff]` 会漏**：负责人列的连接符写成全角 `；` `：` 会让 EN 页残留中文标点，
> 但汉字正则返回 0。**必须带上 `\u3000-\u303f` 与 `\uff00-\uffef`。**

### 6.4 已知易漏点（每次都要查）

| # | 位置 | 说明 |
|---|------|------|
| 1 | `raw` 原文里对方自己夹带的中文 | 原文原则上逐字保留，但**人名与括号注释要英文化** |
| 2 | `se` 总结里的中文人名 | 如 `Carrie (刘玉)` → `Carrie (Liu Yu)` |
| 3 | `q` 标题里的**全角括号** | `（@Puah）` → `(@Puah)`，否则视觉上仍像中文排版 |
| 4 | **`to` / `cc` 的 `n_en`** | **最高发**：若直接从 `n` 复制（如 `ivanzhong(钟燕清)`），EN 页就出中文 |
| 5 | **`items[].when`** | **最高发**：渲染器没有 `when_en`，EN 页直接复用 `when`。写 `2026-09-16（仅新增参会人，无实质回复）` 会残留中文 |
| 6 | 新增条目的 `qe` 拼接了中文来源标注常量 | 检查生成 `qe` 的代码 |
| 7 | 双语表格的某个列只写了中文而 `qe` 复用了它 | 给每个中文列配 `*_EN` 字典 |

> **交付前先跑数据层字段扫描**（`subject_en` / `sent_en` / `sender_en` / `to|cc.n_en` / `qe` / `se` /
> `when` / `raw` / `cf.en`），比事后扫 HTML 快得多，也能精确定位是哪个 mail 的哪个字段。

### 8.1 JS 烟测写法

从产物 HTML 抽 `<script>` → 用 stub（`document` / `localStorage` / `navigator`）`eval` 后断言：

- `MAILS.length` = 邮件数
- `rows()` 里的备注块数
- `mset()` 后 `noteKeys()` 与 `class="solved"` 是否生效

**两个细节**

1. 桩元素记得带 `focus(){}`（`ddToggle` 会 focus 筛选框；
   缺了会报 `f.focus is not a function` —— 是**桩的问题**不是页面的）
2. **断言不要写死语言**：`h15.indexOf('cf-badge')`、`/one-hour meeting/i` 这类断言在 CN 页必然 FAIL
   （是断言选错了 token，不是页面 bug）。
   断言要么查数据层，要么用 `String.fromCharCode(24847,35265,19981,19968,33268)`
   这种方式兼容中英，**避免把中文写进 JS 文件**

### 8.2 写回往返测试（必跑）

```
桩掉 createWritable() 抓写盘内容
  → 落盘
  → 用空 localStorage 当全新页面重新载入
  → 断言：标记能从烘焙位恢复 / 仍是收起态 / 二次写回不丢
```

> 只测 `bakeHTML()` 会漏掉版本号自增，**这条链路不跑通，「保存成功」就是假的**。

> **改了备注 / 写回逻辑，必须同时跑三样**：`node --check`（语法）、
> 备注烟测（默认收起 + 烘焙位 + EN 零中文）、**写回往返**（写回后重开能恢复）。

### 8.3 回归脚本的期望值要动态

硬编码的期望值会随数据增长失效（如「M1 未解决数 = 1」，
条目从 21 涨到 23 后就 FAIL）。改成**动态写法**：

```js
// 取消标记前先读取当前值，再断言 +1
var before = openCount();
unsetS(key);
ck('取消标记后本封未解决数 +1', openCount() === before + 1);
```

## 9. i18n 与代码约定

### 9.1 `I18N` 字典

所有界面文案集中在 `I18N["zh"]` / `I18N["en"]` 两个 dict，通过 `t = I18N[lang]` 取用。
新增文案时**两个 dict 都要加**，否则英文页会 KeyError 或显示中文。

### 9.2 Python 三引号里的 JS 转义层数（极隐蔽的坑）

`JS = """…"""` 是**非 raw** 字符串，Python 先吃掉一层反斜杠。

| 要在产物 JS 里得到 | 源码必须写 |
|---|---|
| `\'`（单引号字符串内的转义） | `\\'` |
| `\s`（正则） | `\\s` |

**症状**：源码写 `setS(\'MEMO\')` → 产物 `setS('MEMO')` → JS 语法错误 `Unexpected identifier 'MEMO'`
→ 浏览器里表现为**整页白屏无 JS**（最难排查的一类故障）。

**必做**：抽 `<script>` 落盘 → `node --check`。只写 `\s` 还会触发
`SyntaxWarning: invalid escape sequence '\s'`（现在只是告警，未来 Python 版本会变硬报错）。

### 9.3 同文件多编辑必须串行

同一文件的多个 `Edit` 调用**不要放在同一条消息里并行发** —— 并行时后写会覆盖先写，
工具仍返回 success 但改动丢失。**必须串行发送，改完 `grep` 复核一遍再跑。**
