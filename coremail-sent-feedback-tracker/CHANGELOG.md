格式参考 [Keep a Changelog](https://keepachangelog.com/zh-CN/1.1.0/)，版本号遵循 [语义化版本](https://semver.org/lang/zh-CN/)。

## [1.0.0] — 2026-10-04

首个正式版本。把此前在 HP 项目里跑了 8 轮、逐步打磨出来的「发出邮件 → 客户反馈追踪」方法论，
从两个项目内技能（`coremail-tabbit-reader`、`hp-clarification-tracker`）抽象、合并、通用化为一个可复用技能。

### Added — 核心能力

- **抓取层**：Coremail 网页版自动接管 / 一键登录、短关键词搜索、按行文本实时匹配定位邮件、
  会话内连续翻页读取、展开折叠联系人并结构化提取 `from/to/cc`。
- **归集口径**：以「**一封我方发出的邮件 = 一个分组**」为归集单位；
  同一主题的首轮与跟进邮件合并（去 `Re:` / `Fwd:` 前缀比对）；
  `held` 保留区机制 —— 非本人发出的邮件移入 `held` 但不删除、不参与统计。
- **五种反馈载体**（判断错载体就会漏掉整批意见）：
  1. 正文逐条回复（`strip_quote.py` 剥离引用历史）
  2. 表格**彩色字体**批注（`getComputedStyle` 取色 + 按「表格行 × Owner」归属）
  3. 汇总表**追加列/单元格**回复（逐 `<table>` 取行 + 「相邻两层 diff」定位本轮新增）
  4. **Google Docs 评论通知**（`comments-noreply@docs.google.com`）
  5. 会议 / 群聊（记在邮件级 `note` 字段，不建 item）
- **负责人(Owner) 列**：解析正文 `@提及`（昵称 → 人员映射表 + 长键优先正则），
  逐个标注「已回复（带时间）/ 未回复」；不在 @名单里的实际回复人另起「实际回复」行；
  部门型 @提及（如 `@CED`）标为「团队」且不参与判定。
- **⚠ 意见不一致标记**：对方内部答复冲突 / 与我方理解相反 / 自相矛盾时自动打标，
  冲突双方行各标一份。
- **手工备注区**：每条总结下方可勾「已解决」+ 写一条「备忘 / 最终结论」（**单输入框**）。
  默认收起、输入即存、不打断焦点。
- **备注持久化三层**：
  1. localStorage（`键 = 邮件号 + md5(问题文本)[:10]`，中英文两页共用同一份）
  2. **写回本页 HTML 文件**（File System Access API，`/*MEMO-S*/…/*MEMO-E*/` 烘焙位替换）
  3. 固化进数据文件 `memos` / `memos_v` 字段（跨机器不丢）
- **Open items 动态清单**：只列未标记解决的条目，点击跳转到对应邮件；
  顶部三张统计卡片（已解决 / 未解决 / 已加备注）**首帧即显示真实数字**。
- **三件套输出**：中文 HTML + 英文 HTML（**零中文残留**）+ Markdown。
- **版式**：单行下拉式邮件切换器、邮件级信息上移为「邮件头卡片」、
  固定四列 + 固定列宽、回复内容不做内滚动、hover 提示（标题/发件人/时间）、
  状态筛选 chip、当前邮件内关键字搜索。
- **安全边界**：所有浏览器 JS 执行前过 `guards.py` 静态扫描；
  DENY 级（删邮件 / 清会话 / 改账号 / 读密码 / 网络外发 / 动态求值）永不放行；
  CONFIRM 级（发信 / 附件 / 关页 / 改状态 / 点正文链接）需显式环境变量放行。
- **交付发信**：Agent Mail 通道（ASCII 附件名 + 发后核对），不走 Coremail 发信。

### Added — 文档与资产

- `SKILL.md`：主入口，10 节完整工作流 + 口径表 + 校验清单 + 踩坑速查表。
- `README.md`：安装 / 前置条件 / 快速开始 / **首次使用要改的三处配置** / FAQ。
- `references/01-coremail-web-dom.md`：Coremail XT5 DOM 速查、会话遍历、回复全部清单生成。
- `references/02-feedback-extraction.md`：五类载体提取细则 + 昵称考证实例。
- `references/03-data-schema.md`：数据文件完整 schema + 字段口径 + 红线。
- `references/04-render-spec.md`：渲染规范（版式 / i18n / 零中文 / 校验）。
- `references/05-pitfalls.md`：踩坑与修复全表（含上游演进时间线）。
- `scripts/`：**14 个**脚本 —— `tabbit.py`、`guards.py`、6 个 `mail_*.js` 模板、
  `strip_quote.py`、`owner_rules.py`、`render_tracker.py`、**`verify_render.py`**、
  `render_report.py`、`report_template.html`。
- **`scripts/verify_render.py`（新增）**：交付前**静态校验器**，把 SKILL.md §7 清单里
  可自动判定的部分固化成一个命令，退出码 0/1 可直接接 CI：
  - EN 页广义 CJK = 0（失败时打印残留片段 + 区分「窄扫为 0」的全角标点场景）
  - `max-height` = 2（多一处即有人在回复内容里加了内滚动）
  - CN 页 `class='sub'` 计数（偏低即 `en_clean` 串了语言）
  - 负责人列 / 下拉切换器 / Open items / 烘焙位 / 渲染入口 的存在性
  - 抽 `<script>` 跑 `node --check`（捕获「整页白屏」级语法错误）
  - 数据层 `*_en` / `when` / `qe` / `se` / `raw` / `cf.en` 汉字扫描
  - **分级判定**：`mails` 里的中文 = FAIL（污染产物）；`held` 里的 = WARN（不参与渲染）；
    `<span class='sub'>` 内的 = 合法（`en_clean()` 会剔除）
- `examples/minimal_data.json`（新增）：最小可运行示例数据，
  一条主清单邮件（3 条 item，覆盖 `ok` / `part`+`cf` / `none` 三态与 `note`）
  + 一条 `held` 记录。不连邮箱即可验证完整渲染链路。

### 验证记录（2026-10-04）

| 对象 | 结果 |
|------|------|
| `examples/minimal_data.json` → 三件套 | 渲染成功；`verify_render.py` **15 PASS / 0 FAIL** |
| 真实 HP 数据集（9 封 / 136 条 / 80 标记）→ 三件套 | `verify_render.py` **15 PASS / 0 FAIL**（CN `sub`=131、EN CJK=0、`max-height`=2） |
| 全部 7 个 Python 脚本 | `ast.parse()` 全通过 |
| CN/EN 页内嵌 JS | `node --check` 全通过 |

> 校验过程中发现并修正了**两处文档期望值错误**（见下方 Fixed）。
> 另发现真实数据 `held` 中两条的 `n_en` 误填了中文名 —— 按「不擅自改用户数据」原则未改动，
> 由脚本以 WARN 形式报出（该字段不在渲染路径上，不影响产物）。

### Changed — 相对上游技能的调整

- `hp-clarification-tracker` 的输出文件名、界面文案、localStorage key 前缀、
  人员映射表**全部参数化/可替换**，不再绑定 HP 项目。
- 交付前校验从「口头检查」变为 **10 项固定清单**（含写回往返测试），一项不过不交付。
- 「更新流程」明确为**七步**，并在第 0 步强制要求：
  **先取回用户浏览器里的手工标记 + 先确认清单口径**（顺序错了会白跑一轮）。
- 把散落在 SKILL.md 各处的踩坑收敛为**第 9 节的速查表**（浏览器层 / 数据渲染层两张表）。

### Fixed — 本版本已内置的修复

这些是上游演进过程中踩到并修掉的真实缺陷，本版本直接以修复后形态发布：

- **英文页中文残留 364 字**：新增条目把中文来源拼进英文列、描述仅写中文。
  → 修法：每个中文列配对应 `*_EN` 字典，`qe` 走英文版；交付前跑广义 CJK 扫描。
- **EN 页 CJK 扫描漏报**：只扫 `[\u4e00-\u9fff]` 会漏掉全角标点。
  → 改为扫 `[\u3000-\u303f\u4e00-\u9fff\uff00-\uffef]`。
- **CN 页问题子句被静默剥掉**：`q=en_clean(it["q"]) if lang=="zh"` 写反，
  `class='sub'` 计数从 156 掉到 2。
  → 只有英文版才过 `en_clean`，并加「CN 页 sub 计数应有上百个」的回归断言。
- **`en_clean()` 误删英文子句**：无条件剔除 `<span class='sub'>` 会删掉本身就是英文的有效信息。
  → 改为对 sub 内容做中文判定，命中才删。
- **备注键哈希口径不一致**：核对时用「删标签」而非「标签替换为空格」，
  54 条标记只对上 6 条，差点误判为版本错位。
  → 核对前先抄 `item_key()` 原文，并写进文档红线。
- **写回后标记丢失**：写回时未自增 `LS.v`，新浏览器打开时 `BAKED.v > LS.v` 不成立，
  烘焙值被空 localStorage 盖掉 —— 看起来「保存成功」实则白存。
  → 写回前 `LS.v = (LS.v||0)+1`；并强制跑「写回 → 空 localStorage 重载」往返测试。
- **`held` 编号与主清单撞号**：只对 `held` 取 max，生成了与主清单重复的 id。
  → 两边合并取全局 max 再 +1。
- **列表行索引位移导致读到无关邮件**：同一封邮件上午 idx 4、下午 idx 5，
  按 idx 点开误读到工会邮件。
  → 改为「按行文本实时匹配 + 回传 row 文本比对 + `EXPECT MISMATCH` 报错」。
- **打开邮件后二次点击超时**：打开后列表全隐藏（`offsetParent === null`），
  第二次按 idx 点击必然 30s 超时。
  → 改用 read 视图的 `a.u-page-prev` 连续往回走。
- **搜索结果中隐藏行被误点**：114 个 `tr.j-mail` 节点里只有 14 个可见。
  → 先按可见性过滤再取下标。
- **彩色批注归属错误**：按「颜色 → 人」的固定映射会误判（蓝色被多人共用）；
  按 TreeWalker 顺序归属会把批注错挂到上一个领域。
  → 改为「批注写在哪个领域行上就归该领域 Owner」+ 用 `tds[0]` 整格文本匹配。
- **默认黑字回复被漏掉**：只读彩色批注会漏掉默认色的有效回复。
  → 表格类邮件收尾强制回读纯文本正文。
- **`@Lee` 吃掉 `@Leong`**：朴素正则 `@[A-Za-z]+` 得到半截结果。
  → 长键优先 + 末尾否定前瞻。
- **责任人误归属**：只看 `Owner` 列的 `@nick` 会误判（实测某两行答案实际是另一层新加的）。
  → 必须用「相邻两层 diff」交叉验证。
- **`todos` 追加纯字符串导致崩溃**：`TypeError: string indices must be integers`。
  → 强制对象数组结构。
- **Bash heredoc 写含中文脚本解析失败**：混排撇号与中文触发 `unexpected EOF`。
  → 改用文件写入工具落盘，落盘后探测编码再归一 + `ast.parse()` 校验。
- **并行 `Edit` 静默丢改动**：工具返回 success 但改动未落盘，直到运行时 `NameError` 才暴露。
  → 同一文件的多个 Edit 必须**串行**发送，改完 `grep` 复核。
- **Python 三引号里的 JS 转义层数**：`setS(\'MEMO\')` 产出 JS 语法错误 → **整页白屏无 JS**。
  → 源码写 `\\'`；改完必须抽 `<script>` 跑 `node --check`。
- **回归脚本期望值硬编码失效**：条目数增长后旧断言 FAIL。
  → 改为动态断言（先读当前值再断言增量）。
- **Open items chip 口径矛盾**：chip 显示全局数但点击只筛当前邮件。
  → 改为显示本封未解决数，与点击结果一致。
- **文档里的 `max-height` 期望值写错**：原文写「只允许 `.ddlist` **1 处**」，
  实测真实产物是 **2 处**（`.ddlist` + `.todo ol` 的 240px 限高）。
  按错误期望值校验会把正常产物判成失败，进而误导人去「修」本来正确的代码。
  → 已按真实基线修正为 2，并列出两处位置及各自允许的理由。
- **备注模板块的计数口径写错**：原文写「`.memo-hd` / `.memo-pv` / `.memo-bd` 各 = 条目数」，
  实际它们在**静态 HTML 里各只出现 1 次**（是 `rows()` 里的模板字符串，渲染时才循环生成）。
  按错误口径校验永远 FAIL。
  → 改为「静态各 1 次」，真实行数明确指向 JS 运行时烟测。
- **`verify_render.py` 的目录配对 bug**（本版本内自测发现）：
  `find_pair()` 按名字排序取第一个 `*_EN.html`，在同时存在「汇总三件套」与「单封导出」的目录下
  会误取到 `HP_Clarification_M15_EN.html`。
  → 改为以 `*_CN.html` 为锚、取同前缀的 EN，并优先匹配「汇总 / Summary」类文件名。
- **`verify_render.py` 对 `sub` 内中文误报**（本版本内自测发现）：
  数据层扫描把 `<span class='sub'>` 内的中文也判为问题，但渲染器的 `en_clean()`
  **本就该剔除**这类中文（设计如此）。真实数据上误报 14 处。
  → 判定前先剥离 `sub` 段，并把 `held` 里的问题降级为 WARN。

### Known Issues — 已知限制

- **localStorage 按源隔离**：内置预览面板（`127.0.0.1`）与 `file://` 不同源，
  在预览面板里打的标记读不回本地文件。**必须双击本地文件打开 + 点「保存到本页文件」**。
- **写回句柄不跨会话**：浏览器不允许跨会话持有文件句柄，刷新后需再点一次「保存到本页文件」重连。
- **`showSaveFilePicker` 兼容性**：Firefox / Safari 不支持，会降级为「下载更新后的副本」，
  需用户手动替换原文件。
- **搜索不可靠**：Coremail 搜索是模糊/OR 匹配，且连续换关键词可能不生效。
  列「最近邮件」应直接读列表而非依赖搜索。
- **`render_tracker.py` 仍含项目专有常量**：`I18N.title`、输出文件名、
  `STORE` 的 localStorage key 前缀、以及部分表格类邮件的专有解析分支。
  换项目时需按 `README.md` 的「首次使用要改什么」调整。
- **彩色批注的颜色→人映射无法通用**：不同组织/客户端用色习惯不同，
  本技能采用「按领域行归 Owner」策略绕开该问题；若你的场景无 Owner 列，
  需要人工核对（`references/02` 有判断方法）。

## 上游演进时间线

本技能的方法论来自一次真实项目连续 8 轮的重跑。了解这条时间线有助于理解「为什么某些设计是这样的」。

| 日期 | 事件 | 沉淀下来的设计 |
|------|------|----------------|
| 2026-09-02 | 首次用 Tabbit CLI 接管 Coremail，验证「自动登录 + 读取」两分支 | `ensure` 的三种 mode；`--task` 必须前置 |
| 2026-09-04 | 遇到「会话已过期」弹层导致所有点击超时 | 登录判据加「无可见 `.u-dialog`」；重登后自动点列表刷新 |
| 2026-09-17 | 版式从多行页签改单行下拉；新增负责人列、手工备注区、未解决动态清单 | 单页签 + 邮件头卡片；备注键用问题文本哈希 |
| 2026-09-17 晚 | 写回测试暴露「版本号不自增 = 白存」 | 写回前 `LS.v+1`；往返测试成为必跑项 |
| 2026-09-24 | 发现客户反馈大量走 Google Docs 评论通知 | 新增第 4 类载体 + 文档→分组映射 |
| 2026-09-25 | 列表行索引位移导致误读工会邮件 | 放弃 idx 定位，改按行文本实时匹配 |
| 2026-09-27 | 新增 held 条目时与主清单撞号 | `held` 与 `mails` 共用命名空间，取全局 max |
| 2026-09-28 | 为做「回复全部」遍历整条会话取全部收发件人 | 折叠展开 + `a.u-page-prev` 连读；名字去重剔除邮箱形态候选 |
| 2026-10-04 | **抽象为本技能** | 参数化 + 文档化 + 校验清单化 |
